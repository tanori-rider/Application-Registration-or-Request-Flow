### Form Control State Matrix

# Default State
CSS Selectors: input, select, textarea
Visual Indicators: 2px solid gray border, white background, 1.6 line height
Accessibility Role: Baseline state for form controls prior to user interaction.

# Focus State
CSS Selectors: :focus-visible
Visual Indicators: 0.25rem gold outline, 0.2rem offset, maroon drop shadow
Accessibility Role: Satisfies WCAG 2.4.7 & 2.4.13 for high-contrast keyboard navigation.

# Required State
CSS Selectors: input[required], select [required]
Visual Indicators: 0.35rem thick left border accent + visible (required) label text
Accessibility Role: Visually signals the mandatory fields before user entry.

# Valid State
CSS Selectors: :user-valid
Visual Indicators: Green border + light green background tint
Accessibility Role: Provides positive feedback after complete valid entry, preventing premature validation.

# Invalid State
CSS Selectors: :user-invalid
Visual Indicators: Red border + light red background tint
Accessibility Role: Highlights syntax errors upon field blur after user interaction.

# Disabled State
CSS Selectors: button:disabled, input:disabled
Visual Indicators: 55% opacity, cursor: not-allowed, gray border
Accessibility Role: Clearly indicates non-interactive or unavailable actions.

# Server Error
CSS Selectors: .error-summary, .field-error
Visual Indicators: 0.4rem thick red left border, error summary banner, preserved value (2026-11-20)
Accessibility Role: Models server business-logic failure (scheduling conflict) with actionable recovery links.

### Code Defense & Design Rationale

Data Minimization Rationale:
   - Email is marked mandatory because automated digital dispatch confirmations are required by OHS operations.
   - Phone number is explicitly marked optional backup to respect user privacy while providing an optional secondary contact channel for delivery drivers.
   - PII is limited to operational site lead contact details; sensitive client medical or financial records are excluded.

Accessibility & Control Selection:
   - All controls utilize native HTML form elements with explicit `<label for="...">` associations.
   - Helper instructions (`#email-help`, `#phone-help`, `#count-help`, `#date-help`, `#notes-help`) are programmatically linked to their inputs via `aria-describedby` so screen reader users hear constraints prior to entry.
   - Focus indicators use high-contrast 0.25rem gold outlines (`:focus-visible`) meeting WCAG 2.4.7 and 2.4.13.

Error Recovery & State Management:
   - Native HTML attributes (`required`, `type="email"`, `min`, `max`, `step`, `maxlength`) handle client-side validation.
   - The F5 section models a static server-returned business-logic error (scheduling conflict for ZIP 85012 on 2026-11-20), featuring a top `role="alert"` error summary box with in-page anchor links and inline field styling (`aria-invalid="true"`) preserving the rejected input value.
